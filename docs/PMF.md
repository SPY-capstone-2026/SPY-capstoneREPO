# Related Work & 차별성

이 문서는 서비스의 대표 기능과 Moni의 설계 방향을 비교합니다. 경쟁 서비스에 소비 전 지원이나 보상이 전혀 없다는 뜻이 아니며, 효과 검증 결과와 구현 현황을 구분합니다.

---

## 1. 관련 서비스 분석

| 항목 | 뱅크샐러드 | 토스 | 편한가계부 |
| --- | --- | --- | --- |
| 핵심 기능 | 금융정보 연동·통합 자산·자동 가계부 | 일상 금융·자산·소비 관리 | 지출 기록·통계·예산 관리 |
| 소비 전 지원 | 자산·예산 현황 확인과 관리 | 잔액·결제 예정 등 금융 현황 확인 | 예산 설정과 사용 현황 확인 |
| 소비 후 확인 | 항목별 소비·자산 분석 | 거래·소비 현황 확인 | 기간·분류별 기록과 통계 |
| 데이터 처리 방향 | 연결된 금융정보를 통합 | 금융 업무와 정보를 한 앱에서 제공 | 사용자의 수입·지출 기록 정리 |
| 참여·관리 지원 | 정보·분석 기반 관리 | 미션·퀴즈 등 참여형 혜택도 제공 | 기록·예산 대비 지출 관리 |
| 대표 사용자 경험 | 자산과 소비를 함께 파악 | 일상 금융 업무를 편리하게 수행 | 자신의 수입·지출을 정리 |

위 표는 공식 소개에서 확인할 수 있는 대표 방향을 요약한 것입니다. 특정 앱의 전체 기능 목록이나 우열을 평가한 표가 아니며, 모든 앱을 ‘소비 후 기능만 제공’으로 분류하지 않습니다.

공식 확인 경로: [뱅크샐러드](https://www.banksalad.com/) · [토스](https://toss.im/) · [토스 혜택](https://toss.im/service/benefits) · [편한가계부](https://ko.realbyteapps.com/). 서비스 내용은 변경될 수 있으므로 외부 발표 시 해당 소개를 다시 확인합니다.

Moni가 집중하는 문제는 금융정보 자체의 통합보다 **현재 소비 흐름을 보고 오늘 실행할 행동을 정하기 어려운 점**입니다. 과거 기록과 월말 예상 지출을 하루 챌린지로 연결하고, 완료 표시 이후 등록된 기록으로 결과를 검증합니다.

## 2. Moni의 차별성과 접근

### 소비 이전 개입

소비하기 전에 볼 수 있는 카테고리별 지출 한도·무지출 목표를 제공합니다. ‘예측 → 목표 → 실천 → 검증 → 성장’이 연결된다는 점을 강조합니다.

여기서 개입은 결제 승인 차단·실시간 계좌 감시·결제 직전 자동 푸시가 아닙니다. 현재 구현은 앱에서 조회하는 목표와 기록 기반 검증이며, 은행 API 실시간 연동은 확인되지 않았습니다.

### 시계열 예측 기반 개인화

현재 코드의 예측 경로는 **statsmodels ARIMA(7,0,1)**와 평균 기반 대체 예측입니다. 거래를 카테고리별 일 단위로 집계하고, 누락 날짜를 0으로 채운 시계열을 사용합니다.

데이터 조건이 충족되면 ARIMA를 호출하고, 부족하거나 예측이 실패한 경우 최근 최대 30일 평균을 사용합니다. 월말 예상 지출과 예산 압박도, 남은 예산을 바탕으로 목표를 계산합니다. 모델 선택 과정의 과거 결과와 현재 적용 모델은 [비교 리포트](./AI%20예측모델%20비교리포트.md)에서 구분합니다.

LLM은 지출 금액을 결정하거나 달성을 판정하지 않고 서버가 정한 목표와 통계를 자연어로 표현합니다. 수입일·소비 성향이 계정에 저장되어 있다는 사실을 현재 예측에 직접 반영된 개인화 요소라고 과장하지 않습니다.

### 행동 유도 구조 (챌린지 + 보상)

완료 표시는 `VERIFYING`으로 저장되고 즉시 보상을 지급하지 않습니다. 다음 날 해당 날짜의 등록 지출과 한도를 비교하여 성공·실패를 판정합니다. 성공 시 XP가 누적되고 레벨업 때 포인트·지정 아이템을 받을 수 있습니다.

사용자는 아이템 구매·장착·캐릭터와 방 꾸미기를 통해 성장을 확인하고, 친구의 공개 프로필과 방을 볼 수 있습니다. 보상이 있다는 사실 자체보다 **소비 목표의 실천과 검증을 성장에 연결한다는 점**이 차별 요소입니다.

게이미피케이션이 실제 참여 지속성·소비 감소를 개선하는지는 사용자 실험이 필요한 가설입니다.

### 인식하는 한계

- 분석과 검증은 사용자가 입력·가져온 데이터의 완전성과 정확성에 의존합니다. 실제 모든 은행 거래를 자동 수집하는 것은 아닙니다.
- 파일 가져오기 서버 API와 UI는 있으나 확정 요청·응답 매핑 불일치가 남아 있어 정상 사용을 위해 연결 보완이 필요합니다.
- 정산 팝업의 `/challenges/settlements` 호출은 현재 서버 `/challenges/history`와 일치하지 않습니다.
- 챌린지의 ARIMA 예측과 리포트의 지출 속도 전망은 다른 계산입니다.
- 한도 없는 기본 챌린지는 현재 승인 정책을 사용할 수 있으며, 모든 목표의 객관적 금액 검증을 보장하지 않습니다.
- ARIMA의 입력 분기·기간 경계·구간 추정과 대체 모델 표기는 추가 검증 대상입니다.
- 친구 랭킹 API와 실제 화면 연결, 알림 선호 저장과 푸시 전송은 별개입니다.
- 장기 행동 변화·실사용 정확도·사용자 유지율에 대한 새로운 측정 결과는 이 갱신에서 추가하지 않았습니다.

## 3. 요약

| 항목 | 비교 서비스의 대표 방향 | Moni의 중점 |
| --- | --- | --- |
| 소비 이해 | 자산·거래·통계·예산 확인 | 예측 결과를 하루 목표에 연결 |
| 소비 전 지원 | 예산·잔액·예정 지출·정보 제공 | 예상 지출과 남은 예산 기반 챌린지 |
| 주요 흐름 | 금융정보를 파악하고 관리 | 예측 → 실천 → 검증 → 성장 |
| 목표의 근거 | 서비스별 관리 방식 | 소비 시계열·예산 압박도·남은 예산 |
| 참여 동기 | 서비스별 알림·혜택·관리 기능 | XP·레벨업·꾸미기·친구 교류 |
| 검증 과제 | 앱별 성과와 사용성은 별도 확인 | 실제 소비 변화·지속 참여 효과 검증 |

**Moni — ‘얼마를 썼는지’에서 ‘오늘 어떤 소비를 실천할지’로 연결하는 서비스.**
