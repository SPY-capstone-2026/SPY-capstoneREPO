# Moni Test Scenario

이 문서는 Moni의 주요 기능을 시연하거나 통합 테스트할 때 따라갈 수 있는 체크리스트입니다.

Moni의 핵심 흐름은 다음과 같습니다.

```text
소비 기록 입력
→ 월말 예상 지출 확인
→ 예산 압박도 확인
→ 오늘의 챌린지 생성
→ 챌린지 완료
→ XP / 레벨 반영 확인
```

---

## 1. 테스트 환경

### 백엔드 실행

```bash
cd api
uvicorn main:app --reload
```

백엔드 문서 확인:

```text
http://localhost:8000/docs
```

### 프론트엔드 실행

```bash
cd frontend/mobile
npx expo start --web --clear
```

### 프론트 환경 변수

`frontend/mobile/.env.local` 또는 배포 환경 변수에 아래 값을 설정합니다.

로컬 백엔드 사용 시:

```env
EXPO_PUBLIC_API_BASE_URL=http://localhost:8000
```

배포 백엔드 사용 시:

```env
EXPO_PUBLIC_API_BASE_URL=https://spy-capstonerepo-production.up.railway.app
```

## 2. 시연용 계정

시연용 계정 예시는 다음과 같습니다.

```text
이메일: office@moni.app
비밀번호: 1234
```

계정이 없다면 회원가입 화면에서 같은 정보로 생성합니다.

---

## 3. 사전 확인

테스트 전 아래 항목을 확인합니다.

```text
□ 백엔드 서버가 실행 중이다.
□ 프론트엔드가 Expo Web으로 실행 중이다.
□ 프론트의 API Base URL이 올바르다.
□ 브라우저 콘솔에 CORS 오류가 없다.
□ 로그인 API가 정상 동작한다.
```

## 4. 인증 테스트

### 목표

사용자가 계정을 만들고 로그인한 뒤, 사용자 정보를 정상적으로 조회할 수 있는지 확인합니다.

### 절차

1. 로그인 화면에 접속합니다.
2. 시연용 계정으로 로그인합니다.
3. 계정이 없다면 회원가입을 진행합니다.
4. 로그인 후 홈 화면으로 이동하는지 확인합니다.
5. 마이페이지에서 사용자 정보가 표시되는지 확인합니다.

### 확인 항목

```text
□ 회원가입이 정상적으로 완료된다.
□ 로그인이 정상적으로 완료된다.
□ 로그인 후 홈 화면으로 이동한다.
□ 마이페이지에 이메일, 수입 유형, 수입일, 소비 성향이 표시된다.
□ 인증이 필요한 화면에서 401 오류가 반복되지 않는다.
```

## 5. 마이페이지 테스트

### 목표

사용자 정보 수정과 XP / 레벨 표시가 정상적으로 동작하는지 확인합니다.

### 절차

1. 마이페이지로 이동합니다.
2. 수입 유형을 수정합니다.
3. 수입일을 수정합니다.
4. 소비 성향을 수정합니다.
5. 저장 후 값이 유지되는지 확인합니다.
6. XP와 레벨이 표시되는지 확인합니다.

### 확인 항목

```text
□ 사용자 정보가 실제 API 값으로 표시된다.
□ 수입 유형 수정이 가능하다.
□ 수입일 수정이 가능하다.
□ 소비 성향 수정이 가능하다.
□ 저장 후 새로고침해도 수정값이 유지된다.
□ XP와 레벨이 표시된다.
```

## 6. 소비 기록 테스트

### 목표

지출 추가, 수정, 삭제가 실제 API와 연결되어 동작하는지 확인합니다.

### 절차

1. 소비 탭으로 이동합니다.
2. 지출 추가 버튼을 누릅니다.
3. 날짜, 결제처, 금액, 카테고리를 입력합니다.
4. 저장합니다.
5. 최근 지출 목록에 새 지출이 표시되는지 확인합니다.
6. 방금 추가한 지출을 수정합니다.
7. 날짜, 금액, 결제처, 카테고리 중 하나 이상을 변경합니다.
8. 수정값이 목록에 반영되는지 확인합니다.
9. 해당 지출을 삭제합니다.
10. 목록에서 제거되는지 확인합니다.

### 예시 입력값

```text
날짜: 2026-06-02
결제처: 스타벅스
금액: 5800
카테고리: 카페
```

```text
날짜: 2026-06-04
결제처: 김밥천국
금액: 9200
카테고리: 식비
```

```text
날짜: 2026-06-07
결제처: 올리브영
금액: 24000
카테고리: 쇼핑
```

### 확인 항목

```text
□ 지출 추가가 가능하다.
□ 지출 날짜를 직접 지정할 수 있다.
□ 최근 지출 목록에 추가한 항목이 표시된다.
□ 지출 수정이 가능하다.
□ 수정 후 서버 데이터 기준으로 목록이 갱신된다.
□ 지출 삭제가 가능하다.
□ 삭제 후 목록에서 제거된다.
```

## 7. 날짜 기준 테스트

### 목표

지출 날짜가 월간 리포트 계산에 제대로 반영되는지 확인합니다.

### 절차

1. 이번 달 날짜로 지출을 추가합니다.
2. 홈과 리포트에서 이번 달 지출에 반영되는지 확인합니다.
3. 기존 지출의 날짜를 지난달로 수정합니다.
4. 홈과 리포트의 이번 달 지출에서 제외되는지 확인합니다.
5. 다시 이번 달 날짜로 수정합니다.
6. 이번 달 지출에 다시 포함되는지 확인합니다.

### 확인 항목

```text
□ 이번 달 날짜의 지출은 월간 리포트에 포함된다.
□ 지난달 날짜의 지출은 이번 달 리포트에서 제외된다.
□ 날짜 수정 후 홈 / 소비 / 리포트 수치가 일관되게 반영된다.
```

---

## 8. 예산 관리 테스트

### 목표

카테고리별 월 예산, 알림 기준, 미션 포함 여부가 정상적으로 수정되는지 확인합니다.

### 절차

1. 소비 탭으로 이동합니다.
2. 카테고리별 예산 상태 영역을 확인합니다.
3. 카테고리를 선택합니다.
4. 월 예산을 수정합니다.
5. 알림 기준을 수정합니다.
6. 오늘의 미션 후보 포함 여부를 수정합니다.
7. 저장합니다.
8. 예산 게이지와 상태 문구가 바뀌는지 확인합니다.
9. 새로고침 후에도 값이 유지되는지 확인합니다.

### 확인 항목

```text
□ 카테고리별 예산 목록이 표시된다.
□ 월 예산 수정이 가능하다.
□ 알림 기준 수정이 가능하다.
□ 오늘의 미션 후보 포함 여부 수정이 가능하다.
□ 저장 후 값이 유지된다.
□ 예산 게이지가 수정된 예산 기준으로 반영된다.
```

6. 소비 탭에서 지출을 추가한 뒤 홈으로 돌아와 수치가 반영되는지 확인합니다.

### 확인 항목

```text

□ 월말 예상 지출이 표시된다.
□ 예산 대비 상태가 표시된다.
□ 지출 추가 후 홈 수치가 갱신된다.
```

## 11. 챌린지 테스트

### 목표

오늘의 챌린지 조회, 생성, 완료, 완료 취소가 정상적으로 동작하는지 확인합니다.

### 절차

1. 챌린지 탭으로 이동합니다.
2. 오늘의 챌린지가 표시되는지 확인합니다.
3. 챌린지가 없으면 챌린지 생성을 실행합니다.
4. 생성된 챌린지의 카테고리, 문구, XP를 확인합니다.
5. 챌린지를 완료합니다.
6. 완료 상태로 바뀌는지 확인합니다.
7. 마이페이지에서 XP / 레벨 반영을 확인합니다.
8. 완료된 챌린지를 다시 눌러 완료 취소합니다.
9. XP / 레벨이 다시 반영되는지 확인합니다.

### 확인 항목

```text
□ 오늘의 챌린지 조회가 가능하다.
□ 챌린지가 없을 때 생성이 가능하다.
□ 챌린지 생성 후 목록에 표시된다.
□ 챌린지 완료가 가능하다.
□ 완료 후 XP가 증가한다.
□ 완료 취소가 가능하다.
□ 완료 취소 후 XP가 재반영된다.
```

## 12. AI / fallback 흐름 확인

### 목표

챌린지 생성 API가 정상적으로 동작하고, 소비 데이터가 부족한 경우에도 fallback 챌린지를 제공하는지 확인합니다.

### 절차

1. 새 계정 또는 소비 데이터가 적은 계정으로 로그인합니다.
2. 챌린지 탭에서 챌린지를 생성합니다.
3. 챌린지가 생성되는지 확인합니다.
4. 백엔드 응답에 `ai_metadata`가 포함되는지 확인합니다.

### 확인 항목

```text
□ 소비 데이터가 부족해도 챌린지가 생성된다.
□ 챌린지 응답에 ai_metadata가 포함된다.
□ fallback 흐름은 사용자 화면에 개발자용 문구로 노출되지 않는다.
□ 사용자는 자연스러운 챌린지 문구만 확인한다.
```

### 목표

사용자 화면에 개발자용 표현이 노출되지 않는지 확인합니다.

### 확인하면 안 되는 문구

```text
mock
fallback
임시
테스트용
API 연결 예정
```

### 확인 항목

```text
□ 사용자 화면에 mock 문구가 보이지 않는다.
□ 사용자 화면에 fallback 문구가 보이지 않는다.
□ 사용자 화면에 임시 / 테스트용 문구가 보이지 않는다.
□ 사용자 화면에 API 연결 예정 문구가 보이지 않는다.
```

## 15. 테스트 후 기록할 내용

테스트 후 아래 내용을 기록하면 좋습니다.

```text
테스트 날짜:

수정이 필요한 항목:
```

```text
테스트 날짜: 2026-06-20
테스트 브랜치: readme
백엔드 실행 환경: local FastAPI
프론트 실행 환경: Expo Web
시연 계정: demo@moni.app
통과한 항목: 로그인, 지출 추가, 리포트 반영, 챌린지 생성
실패한 항목: 없음
수정이 필요한 항목: 없음
```
