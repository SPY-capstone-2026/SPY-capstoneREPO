# Moni

**GitHub description:** AI-powered spending prediction and personalized challenge engine for habit-changing consumption coaching

Moni는 사용자의 과거 소비 패턴을 분석해 미래 지출을 예측하고, 그 결과를 바탕으로 **오늘 바로 실천할 수 있는 개인화 챌린지**를 생성하는 소비 습관 코칭 서비스 MVP입니다.

현재 저장소는 완성형 서비스 전체보다, **핵심 로직의 구현과 검증**에 초점을 둡니다. 즉, 카페 소비 예측 실험, 예산 압박도 기반 챌린지 생성, 재현 가능한 테스트 코드, 데모 스크립트를 통해

> **“과거 소비 데이터가 실제 행동 개입형 챌린지로 이어질 수 있는가?”**

를 직접 확인할 수 있도록 구성한 레포지토리입니다.

---

## 프로젝트 한눈에 보기

### 해결하려는 문제
기존 가계부·소비 관리 서비스는 사용자가 **얼마를 썼는지 기록하고 통계를 보여주는 것**에는 강하지만, 실제로 **오늘 어떤 소비 행동을 해야 하는지 알려주지 못하는 경우**가 많습니다.

### 기술 솔루션
사용자의 과거 소비 패턴을 분석해 **향후 소비를 예측**하고, 예측 결과와 예산 대비 압박도를 반영해 **당일 맞춤형 챌린지**를 생성합니다.

### 기대 효과
사용자는 단순히 월말에 반성하는 것이 아니라, **소비가 일어나기 전에 개입받고**, 작은 실천을 반복하면서 소비 습관을 바꿀 수 있습니다.

### MVP 핵심기술
**과거 소비 데이터 → 지출 예측 → 예산 압박도 계산 → 오늘의 챌린지 생성**

---

## 문제 정의

많은 사람들은 예산을 세우지만 실제 행동으로 이어가지 못합니다.  
"카페를 너무 자주 간다", "충동구매를 줄여야 한다"는 사실은 알고 있어도, 정작 **오늘 어떻게 행동해야 할지**는 알기 어렵습니다.

기존 소비 관리 앱은 대체로 다음 흐름에 머무릅니다.

- 소비 기록
- 월간/주간 통계 제공
- 카테고리별 지출 요약

이 구조는 **쓴 뒤에 확인하는 사후 분석**에는 유용하지만, 소비가 실제로 발생하려는 순간에는 개입하지 못합니다. 그 결과 사용자는 자신의 소비 습관을 "이해"는 하더라도, "바꾸는" 데 어려움을 겪습니다.

이 프로젝트는 이러한 한계를 해결하기 위해, **소비 패턴을 예측하고 그 결과를 행동 단위 챌린지로 연결하는 구조**를 제안합니다.

> 핵심 문제: 소비 습관은 월간 통계가 아니라 **오늘의 행동**으로 결정된다. 기존 앱은 기록 도구일 뿐, 행동 변화 도구가 아니다.

---

## 기술 솔루션

현재 MVP의 핵심은 **예측 기반 소비 코칭 엔진**입니다.

시스템은 다음 순서로 동작합니다.

1. 사용자의 과거 소비 데이터를 입력받습니다.
2. 시계열 패턴을 바탕으로 향후 소비를 예측합니다.
3. 예측 소비 총액과 월 예산을 비교해 **예산 압박도**를 계산합니다.
4. 압박도에 따라 챌린지 난이도를 결정합니다.
5. 난이도에 따라 오늘의 소비 챌린지와 보상 XP를 제안합니다.

현재 테스트 코드는 이 흐름을 **합성 카페 소비 데이터**로 재현합니다.

---

## 최종 MVP 소프트웨어는 무엇인가

이 프로젝트의 최종 MVP는 사용자가 소비 내역과 목표를 입력하면, 시스템이 이를 분석해 **오늘 실천할 수 있는 맞춤형 소비 챌린지**를 제안하고, 그 수행 결과에 따라 **보상과 캐릭터 성장**으로 이어지는 소비 코칭 프로토타입입니다.

즉, 사용자는 단순히 “이번 달에 얼마를 썼는지”를 확인하는 것이 아니라, **오늘 어떤 소비 행동을 해야 하는지** 안내받게 됩니다.

예를 들어,

- 카페 소비가 목표 대비 빠르게 증가하면  
  → **“오늘 카페 0원”** 같은 강한 챌린지가 제안됩니다.
- 예산 압박도가 중간 수준이면  
  → **“오늘 카페 한 번만”**, **“5,000원 이하”** 같은 제한형 챌린지가 생성됩니다.
- 비교적 안정적인 페이스라면  
  → **“아메리카노만 마시기”** 같은 완화된 챌린지가 제안됩니다.

즉, 이 소프트웨어는 **“얼마 썼는지 알려주는 앱”** 을 넘어서,  
**“오늘 뭘 해야 하는지 알려주는 소비 습관 코칭 엔진”** 을 만드는 것을 목표로 합니다.

## 입력 데이터

현재 저장소의 테스트 파이프라인은 다음 정보를 사용합니다.

- 일별 소비 금액
- 날짜 정보
- 최근 소비 패턴
- 월 예산
- 예측 구간의 총 지출 합계

현재 버전에서는 실제 금융 데이터 대신 **재현 가능한 합성 카페 소비 데이터**를 생성해 실험합니다.

---

## 출력 결과

테스트 파이프라인은 다음 결과를 생성합니다.

- **predicted_total**: 예측 기간 총 소비액
- **predicted_range**: 예측 구간 하한~상한
- **budget_pressure**: 예산 대비 압박도
- **difficulty**: EASY / MEDIUM / HARD
- **challenge_text**: 오늘의 챌린지 문구
- **save_target**: 절약 목표 금액
- **xp_reward**: 달성 보상 XP
- **forecast metrics**: MAE / RMSE / MAPE

## 왜 이 기술이 핵심기술인가

이 프로젝트의 고유 핵심기술은 단순한 가계부 UI가 아니라, **소비 패턴을 미래 행동 개입형 챌린지로 연결하는 구조 자체**입니다.

이 기술이 핵심인 이유는 다음과 같습니다.

- 단순 기록/통계 제공이 아니라, **예측 결과를 오늘의 행동 지침으로 변환**합니다.
- 사용자의 소비 흐름이 어떤 방식으로 챌린지에 반영되는지 **설명 가능성**이 있습니다.
- 테스트 코드와 데모 스크립트를 통해 실행 과정을 직접 보여줄 수 있습니다.
- 향후 LLM, 앱 UI, 소셜 기능과 연결되더라도 **중심 엔진으로 확장**할 수 있습니다.

---

## 기대 성과와 사용자 효능

이 프로젝트의 기대 성과는 단순히 예쁜 소비 관리 앱을 만드는 데 있지 않습니다. 실제로는 사용자가 **소비 습관을 장기적으로 바꿀 수 있도록 돕는 것**이 목표입니다.

구체적인 사용자 효능은 다음과 같습니다.

- 월말 통계를 기다리지 않고 **오늘 바로 행동할 수 있는 목표**를 받습니다.
- 예산 압박도에 따라 다른 수준의 챌린지를 받아 **개인화된 개입**을 경험할 수 있습니다.
- 챌린지와 XP 구조를 통해 **지속적인 실천 동기**를 얻을 수 있습니다.
- 향후 주간 리포트, 캐릭터 성장, 소셜 기능과 연결하면 더 확장성 있는 행동 변화 서비스로 발전할 수 있습니다.

즉, 기대효과는 **“소비를 기록하는 서비스”** 하나를 더 만드는 것이 아니라,  
**소비 행동 자체를 바꾸도록 돕는 예측 기반 코칭 소프트웨어**를 만드는 데 있습니다.

## 핵심 실험과 결과

이 저장소는 핵심기술을 설명에만 그치지 않고, **직접 실행 가능한 형태로 검증**합니다.

### 실험 목적
- 과거 소비 패턴을 기반으로 향후 소비를 예측할 수 있는지 확인
- 예측 결과가 예산 압박도로 변환되는지 확인
- 압박도가 실제 챌린지 난이도와 문구 변화로 이어지는지 확인
- 전체 흐름이 재현 가능하게 동작하는지 확인

### 실행 방법

Python 3.10+ 환경에서 아래 명령어를 실행합니다.

```bash
pip install -r requirements.txt
python tests/test_moni_pipeline.py
python scripts/run_moni_demo.py
```

### 실행 시 확인되는 내용
- 합성 소비 데이터 기반 train/test 분할
- Prophet 예측 결과
- 실제 총 소비액과 예측 총 소비액 비교
- MAE / RMSE / MAPE
- 예산 압박도와 챌린지 난이도
- 생성된 챌린지 문구와 XP 보상

## 대표 실험 예시

### 1) 예산 압박도가 높은 경우

입력 조건 예시:

```text
예측 총 소비액 > 월 예산의 90%
```

생성 결과 예시:

```text
difficulty: HARD
challenge: 오늘 카페 0원! 집에서 커피 마시면 나 레벨업할 수 있어 🔥
xp_reward: 50
```

해석:
- 현재 소비 페이스가 예산을 강하게 압박하는 상황입니다.
- 따라서 가장 강한 수준의 챌린지가 생성됩니다.
- 사용자의 행동을 즉시 제어하는 방향으로 개입합니다.

---

### 2) 예산 압박도가 중간인 경우

입력 조건 예시:

```text
예측 총 소비액 ≈ 월 예산의 70% ~ 90%
```

생성 결과 예시:

```text
difficulty: MEDIUM
challenge: 오늘 카페 한 번만! 두 번째 욕구는 물로 이겨내자 🧊
xp_reward: 30
```

해석:
- 위기 상황은 아니지만 소비 조절이 필요한 단계입니다.
- 완전 금지형보다 제한형 챌린지가 더 적합합니다.

---

### 3) 예산 압박도가 낮은 경우

입력 조건 예시:

```text
예측 총 소비액 < 월 예산의 70%
```

생성 결과 예시:

```text
difficulty: EASY
challenge: 오늘은 아메리카노만! 라떼는 내일의 나에게 양보해 😊
xp_reward: 10
```

해석:
- 현재 소비 페이스가 비교적 안정적입니다.
- 챌린지는 유지형 또는 약한 개입형으로 생성됩니다.

## 현재 결과 해석

현재 모델은 프로토타입 단계이기 때문에 실제 상용 금융 서비스 수준의 정밀도를 주장하지는 않습니다. 그러나 **소비 데이터의 차이를 예측값 차이로 연결하고, 그 차이를 다시 챌린지 변화로 연결하는 기본 흐름은 재현 가능**합니다.

현재 결과의 핵심 의미는 **“예측 정확도만 최고다”** 에 있지 않습니다.  
오히려,

> **소비 패턴 변화 → 예측값 변화 → 예산 압박도 변화 → 챌린지 변화**

의 연결성이 실제 코드 수준에서 작동한다는 점을 보여주는 데 있습니다.

즉, 이 MVP의 실험 목적은 단순한 예측 정확도 경쟁이 아니라, **예측이 실제 행동 개입 구조로 연결될 수 있는지 검증하는 것**입니다.

- 현재 챌린지 생성은 규칙 기반이며 개인화 요소가 제한적입니다.
- 카페 소비 시나리오에 집중한 MVP 수준입니다.
- 장기적인 행동 변화 효과는 아직 실사용자 검증 전입니다.

그럼에도 현재 저장소는 다음을 분명히 보여줍니다.

- 문제 정의가 분명합니다.
- 기술 솔루션이 코드 수준에서 실행 가능합니다.
- MVP 핵심기술이 무엇인지 설명 가능합니다.
- 테스트 코드와 실험 흐름을 제3자가 재현할 수 있습니다.
